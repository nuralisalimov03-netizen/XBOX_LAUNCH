# Архитектура SeriesCore

Целевая платформа: **Xbox Series X|S** (AMD Zen 2 + RDNA 2, ОС на базе Windows Core OS с Hyper-V).

## Уровень 0. Контейнеры и хранилище (`containers`)

Каталог: `seriescore/` (этот модуль — CLI-каркас в `seriescore.py`).

- **XVD** (Xbox Virtual Disk) — контейнер диска; в упакованном виде — **XVC**.
- Первый шаг (реализован частично): чтение заголовка, поиск сигнатуры `XVD`,
  снятие отпечатка (размер, хеш первых байт).
- Расшифрование XTS-AES **не входит** в проект — только чтение метаданных
  и прозрачных (незашифрованных) областей.

## Уровень 1. Ядро и системные API (`kernel`)

ОС консоли — близкий родственник Windows. Значит, реалистичная стратегия —
**API-уровневая эмуляция**: перехват вызовов игры (NT-подобные системные вызовы,
Xbox-сервисы) и их переадресация на хостовую ОС. Это тот же подход, что у
 современных быстрых эмуляторов первого Xbox (xemu) — не трансляция CPU, а шимы системных вызовов.

Требуется:

- таблица системных вызовов (нужно её восстановление из легально полученных дамп-символов);
- планировщик потоков (в основном — прокидывание на host threads);
- память: единое адресное пространство с флагами доступа;
- сервисы Xbox (профиль, сохранения, лицензии) — стабы по мере изучения.

## Уровень 2. Графика (`video`) — самый тяжёлый модуль

Игры рисуют через **DirectX 12 Ultimate**. Варианты реализации:

1. **Запись и реплей команд** (command capture + replay): игра формирует command
   list, мы воспроизводим его на хостовом Vulkan/D3D12. Медленнее по CPU, зато
   переносимо.
2. **Нативный RDNA 2** (только видеокарты AMD RX 6000+): идеал «быстрой» эмуляции,
   но зависит от того, насколько ABI команд совпадает — требуется исследование.

Ожидаемые сложности: mesh shaders, VRS (variable rate shading), sampler feedback,
DirectStorage — все доступны в современных ПК-семействах, но требуют маппинга.

## Уровень 3. Звук, ввод, сеть

- **audio**: захват звонков в аудиодвижок консоли и вывод через стандартный
  аудиостек хоста;
- **input**: геймпад через XInput/GameInput → HID хоста;
- **net**: эмуляция XNet для сетевых протоколов игры (без доступа к живым
  сервисам Xbox Live).

## Уровень 4. Оболочка (`ui`)

Интеграция с лаунчером `xbox_launcher.py`: модуль Store/Xbox app подскажет,
какие из ваших легальных Series X|S-игр уже запускаются официальным путем,
а XVD-образ будет разбираться этим CLI.

## Поток данных (целевой)

```
XVD/XVC образ → containers (метаданные, поиск разделов)
              → kernel (загрузка исполняемого PE-модуля игры, шимы вызовов)
              → video (перехват D3D12U → Vulkan/D3D12 хоста)
              → audio / input / net (перевод на API хоста)
              → ui (окно, настройки, профиль)
```

## Открытые вопросы (требуют исследования)

1. Полная карта syscall-поверхности ядра Series X|S.
2. Совместимость ABI D3D12U-командного потока с хостовым RDNA 2.
3. Форматы метаданных XVC-упаковки (публичных описаний мало).
4. Скорость хостового CPU (нужен запас — Zen 3/4 желательно).
